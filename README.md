# ComfyUI-PJ-SegmentSampler

MiniMax H3 分段生成与潜空间精修。支持长视频接力、已有结果低降噪局部回修，以及看完高清结果后回修一采并更新对应二采。保留标准 LATENT 接口、原节点标识和旧工作流参数迁移。

## 五个节点

| 节点 | 职责 |
|---|---|
| PJ_SegmentPlanner | 规划时间窗口；按真实输入长度执行，未接媒体时按约 15 秒预览。图像、音频可用于播放器 |
| PJ_H3EditPrepare | 组合原视频编码潜空间、目标 AV 潜空间和外部空间遮罩；不内置 SAM 或视频编码 |
| PJ_H3SegmentContext | 按段重建 H3 提示词、参考素材条件，并可加入前段运动引导；不替代规划器 |
| PJ_FirstPass_SegmentSampler | 整段生成、连续分段生成、旧结果局部重绘；第二输出仍是首段采样潜空间 |
| PJ_SegmentSampler | 高清分段精修、局部替换、累计一采变更更新；输出完整采样结果及完整去噪结果 |

    官方一采结果 → PJ 一采：载入回修基准 ─┬→ H3 潜空间放大 → PJ 二采 → 最后解码
    PJ 一采直接生成 ──────────────────┘                     ↑
    PJ 一采完整结果 ───────────────────────────────→ source_result
    规划器、H3 分段条件准备（可选）──────────────────→ 一采、二采

二采的 source_result 直接连接一采完整结果，用于版本和时间范围关联，不依赖第三方放大器保留自定义字典字段。放大器必须保持时间长度。中间不解码生成结果；当前仍完整执行所接潜空间放大器，只把二采精修限制在目标区域。

## 高清后局部回修

先完成一次一采和二采，再选择需要修复的段或时间。新增操作与旧采样模式分开，旧工作流不会自动变成低降噪重绘。

| 需求 | 一采操作 | 二采操作 |
|---|---|---|
| 从 PJ 开始生成 | 原采样方式 | 常规精修 |
| 导入官方等已有结果 | 载入回修基准 | 常规精修 |
| 只修一采 | 仅重绘目标段 | 用执行阶段开关跳过放大、二采 |
| 修一采并更新高清 | 仅重绘目标段 | 更新一采变更 |
| 补齐此前累计修改 | 复用一采结果 | 更新一采变更 |
| 一采正常，只修二采 | 复用一采结果 | 仅重做目标段 |
| 查看已有高清结果 | 复用一采结果 | 复用高清结果 |

接入官方结果时，将其完整 LATENT 接到一采的 repair_baseline，先执行“载入回修基准”。之后切到“仅重绘目标段”或“复用一采结果”，使用当前会话保存的结果，不重新请求原始采样链。要换成另一条官方成片，再显式选择“载入回修基准”。修复仍需连接匹配的引导器、噪声和采样算法。

局部重绘以**上次成功结果**初始化，默认降噪 0.4；单独的调度器与步数生成修复 SIGMAS，不再缩放原始一采调度。0 表示不采样。降噪不是修改百分比：低强度通常保留更多原内容，也可能保留缺陷。

目标段两端潜空间固定，中间允许修改；默认边界为 2 个视频潜步，单位不是画面帧。相邻目标合并后只保护组合区间两端。局部操作保留其余完整结果和原音频，不自动重采后续段；右端目前使用潜空间锁定，不宣称实现了反向多帧运动引导。

时间遮罩仅供本次采样使用，不写入输出；已有空间遮罩继续保留并限制修改范围。没有有效完整结果时明确报错，不把局部操作变成全量采样。新候选成功后才替换旧结果；采样失败、非有限值或提交失败时保留旧版。

相同已完成请求可复用；再次抽卡请改变种子或增加操作编号。已被后续操作取代的近期历史请求不会覆盖较新的结果。若改变段尾动作、需要后续一起变化，使用原采样方式下的“从指定段重做”接力操作。

### 执行阶段开关

[局部回修执行阶段示例](workflows/局部回修_执行阶段示例.json) 使用 ComfyUI 原生 ComfySwitchNode：false 选择一采结果，true 选择放大后二采结果。需要同时设置上述一采、二采操作；开关选择执行分支，不代替操作选择。

开关通过原生惰性执行跳过未选择分支。示例使用未接媒体的纯规则规划器和一个最终输出分支。规划器本身也是预览输出节点：如果把随机生成结果接到它的可选潜空间、图像或音频口，普通队列执行仍会独立运行该来源；其他独立保存、预览输出也可能触发另一分支。需要只复用结果时，请保持规划器为纯规则或断开这些额外输出依赖。采样器复用操作不请求采样输入或规划总线，无需修改 ComfyUI 执行器。

## H3 分段条件与长视频

### 用途页签与分段编辑

一采按整段生成、长视频接力、分段编辑、局部重绘、载入结果、复用结果分 Tab；二采按常规精修、局部重做、更新一采变更、复用结果分 Tab。先选择用途，再显示相关参数。规划器按秒、固定段数、自定义切点分 Tab；条件准备按参考用途和音频用途分组。未接规划器时隐藏无效的分段生成入口；切换用途保留原参数与连线。

条件准备的“编辑分段提示词”打开独立窗口。可一次粘贴完整 JSON，再切换到分段编辑；两个视图共用 `segment_prompts`，切换本身不改写原文。格式错误保留原文并提示位置；接了外部文本输入时在上游编辑。旧的 `{"2":"人物转身"}` 写法继续支持，也可使用结构化条目：

```json
{
  "1": "[Shot 1] Establish the room and both characters.",
  "2": {
    "prompt": "[Shot 1] Close-up of the second character.",
    "transition": "cut",
    "audio_transition": "continue",
    "dialogue": [
      {"speaker": "<Subject 2> (S2)", "text": "[Chinese] 我准备好了。", "start": 15.5, "end": 17.5}
    ]
  },
  "3": {"prompt": "They walk to the window.", "dialogue": []}
}
```

- 全局框放共同的人物、场景与风格；各段框放本段动作与对白。只编码当前段条目，不把控制字段送入文本编码器。
- 对白 `start/end` 是**最终成片中的秒数**，编码时减去本采样窗起点。说话者沿用 H3 的 `(S1)` 等编号，台词包含 `[Chinese]` 等语言标记。`dialogue: []` 明确无对白，省略该字段则完全沿用提示词。提示词只能引导，不能保证模型逐字或准点说话。
- `transition: continue` 默认连续接力；`cut` 在该段开头切镜，取消视频继承和前段运动引导。切镜仍有 H3 网格所需的右侧填充，拼合时裁去；不补重叠损失的尾段。切镜位置随完整结果保存，二采连接 `source_result` 后可在重新分段时读取，避免放大器丢失元数据。
- `audio_transition` 独立控制声音承接或 `reset` 重新生成；普通分段的声音继承还需启用接缝约束与正重叠。局部重绘保留已有音轨与镜头边界，改变切镜设置应重新生成。

### 音频用途

| 页签 | 行为 |
|---|---|
| 生成声音 | 使用当前提示词生成，不传入参考音频；这不等于静音 |
| 参考声音 | 保持原行为，使用配套视频音轨和独立音频作为条件，不保证逐样本复制 |
| 保留音轨 | 连接“指定音轨”和音频 VAE，编码后用原生 AV 遮罩锁住音频；不足长度的波形补静音 |

指定音轨不占用参考 `<Audio N>` 编号。需要原始声音逐样本不变时，将原始 AUDIO 直接接最终视频合成；音频 VAE 编码再解码不等于无损复制。二采开启“保留一采原音频”时，以输入音频为准；局部回修也保留已有音轨。新模式没有改变加速 LoRA 或采样步数，尚不代表额外含糊语音问题已经通过真实成片验收。

PJ_H3SegmentContext 接收 CLIP、全局提示词和可选分段补充提示词，例如 {"2":"人物转身"}。连接视频 VAE 时同时编码参考潜空间；不接 VAE 时参考素材只进入语义编码。保留原引导器的模型、CFG、负面条件和采样策略。

同一节点可设置目标宽度、高度和总帧数，创建完整目标 AV 潜空间。总帧数按 24 FPS 的 `17n+5` 向下对齐（不足 5 帧时使用 5 帧）；输出顺序为 **H3分段上下文、目标音视频潜空间、基础正面条件**。分别连接 PJ 采样器上下文、编辑区域准备/一采潜空间、引导器，即可移除原来仅用于目标结构和基础条件的官方参考节点。基础正面条件是无参考的空提示词条件，仅用于建立 PJ 引导器；实际提示词与参考仍由上下文逐段编码，不能把这个输出单独用于官方采样器期待完整参考效果。

目标尺寸仅决定新建潜空间，不限制后续二采：每个窗口按采样输入的真实宽高重建条件。原视频编辑仍需单独提供原视频 VAE 编码底稿及空间遮罩；原音可沿现有音频分支输出。旧工作流可省略新增尺寸输入并继续使用第一个上下文输出，现有 `prepare` Python 接口不变。

图片、视频、视频配套音轨、独立音频均使用官方 Autogrow 动态接口，连接后增加下一个空口，每组最多 100 个口（框架上限）。图片可有不同尺寸，无需合批；`参考图像尺寸` 的 `match` / `max` 直接使用官方规则。旧画布的单路媒体连线自动迁移到对应组第一个口；每个图片口与官方一样只取输入的第一张图，原来接了图片批次的工作流需要改为逐张连接。旧 API JSON 的媒体键需改为 `ref_videos.ref_video_0`、`ref_video_audios.ref_video_audio_0`、`ref_audios.ref_audio_0`，Python prepare 的旧参数仍可使用。

视频配套音轨与视频按接口后缀配对，例如 `ref_video_audio_2` 对应 `ref_video_2`；未接对应视频的音轨会提示连接错误。传入官方编码时，媒体按已连接接口的数字顺序排列，提示词中的 `<Picture 1>`、`<Video 1>` 从 1 开始连续计数，不等于有空缺时的接口后缀。音频标签先包含按视频顺序出现的配套音轨，再包含独立音频。

- **原视频编辑**：所有参考视频按同一绝对时间裁剪，语义编码和 VAE 使用对应片段，配套音轨按各自采样率同步切片。某路素材不足时指出接口及目标段，提示补充素材或改用素材参考，不自动循环或冻结末帧。
- **素材参考**：图片和独立视频不随目标段起点裁剪；视频及配套音轨仍按原生 H3 合法长度裁齐。独立音频保持独立用途。
- **运动上下文**：将前段真实重叠潜空间转成 H3 关键帧引导，不解码生成结果。只使用相位对齐的前向上下文；局部重绘仍以旧结果及双端遮罩为基础。
- 不接此节点时保持已有条件切片路径，不重新编码整片语义条件。已有关键帧引导的空间尺寸必须与采样窗口一致；二采不可直接继承低清关键帧，应按高清尺寸重建。
- 同步参考不保证生成动作逐帧复现参考。

一采“22帧接力”先按目标 AV 潜空间的时长与规划器目标段长切分，再扣除各段间的 22 帧重叠，不为凑满输入时长额外补段。正常切分产生的余段仍保留；仅包含继承区、没有新增画面的余段不生成。各窗就近对齐 H3 帧数，例如 24 FPS 下输入 45 秒、目标段长 15 秒，生成三个 362 帧窗口，去掉两处 22 帧后输出 1042 帧（约 43.42 秒）。音频、空间遮罩和版本范围同步到实际输出长度；二采与局部回修覆盖已有结果，不再次扣短。

普通切点和目标重叠不参与接力规划：连续镜头的后段继承前段最后 7 个视频潜步（22 帧），通过原生遮罩固定；接入 H3 上下文时再加入运动引导。显式切镜使用上文的独立边界规则。每段条件和采样都按窗口处理，完整输入、输出及参考素材仍占内存。

接入 PJ 上下文后，先集中编码本次需要采样的各段条件，卸载编码模型，再连续采样，避免每段在文本编码器、VAE 和 DiT 之间往返加载。条件临时写入本机磁盘，逐段读取，结束或异常后删除；未接上下文保持原路径。后段运动引导仍取刚生成的前段，重跑只准备失效范围，局部重绘只准备选中范围。无需新增接线或开关。

显存不足时仍由 ComfyUI 自动卸载部分模型；该优化减少模型切换，不保证任意分辨率不溢出。量化模型和 LoRA 在不同加载状态下不保证同一种子逐值复现旧版输出；真实验证范围见 [验证报告](docs/VALIDATION.md)。

拼接时后段只交付新增内容，不重复输出 22 帧；音频按 40 Hz 时钟去重。例如两个 192 帧窗口接力得到 362 帧。“从指定段重做”重建当前段及后续依赖，前段缓存缺失或条件改变可能从更早位置开始。普通分段启用运动上下文时，同样使依赖旧前段的缓存失效。

## H3 时间和拼接规则

- 模型时钟为 24 FPS；17n+5 帧对应 5n+2 视频潜步，音频每秒 40 潜步。例如 362 帧对应视频 107 步、音频 603 步。
- 秒数为规划参考，后端就近匹配合法窗口和正重叠；执行依据真实输入长度，约 15 秒预览不决定成片长度。回修不改变已有成片长度。
- 6 秒段长匹配 141 帧；0.5 秒正重叠匹配 5 帧。自动或固定段数模式下，**重叠填 0 就不交付重叠内容**，也不继承前段或附加前段运动引导。合法采样窗仍有必要的右侧填充，拼合时裁除，不把填充显示成重叠。
- 自定义区间以对齐后的实际交集为准，未覆盖区保留输入。22 帧接力始终采用自身规则，不受普通重叠 0 设置影响。
- 完整输出按绝对时间拼合。一采次级“首段潜空间”在采样后为完整合法采样窗口，可能包含填充，不应当作已裁剪交付片段重复拼接。仅载入外部基准、尚未实际采样时，次级输出为完整基准；复用时返回上次保存的次级结果，不为它重新执行规划器。
- 常规二采有正重叠时固定承接已精修视频边界，只保留一份重叠内容；视频不做两份独立画面的加权混合。二采过渡算法只用于非旁路音频。一采旧独立分段模式仍保留原融合选项。

规划器 fps 用于将图像序列时长换算为 H3 预览，不负责重采样上游视频。规划总线可不接；未接时按完整输入采样，隐藏无关分段控件。已取消手动 51 帧吸附开关，旧控件值会迁移。

采样器执行后，目标菜单优先使用当前结果的真实段数；载入整段基准后按其真实长度计算。更改规划规则时重新估算，重新连接来源时清除旧长度。直接段号菜单最多显示 20 段，更后面的目标使用时间或自定义段号；规划器自身仍保留规则预览。

## 空间编辑遮罩

    H3 目标 AV LATENT ─────────────→ 编辑区域准备
    原视频 → 对齐尺寸和长度 → VAE编码 ─→ 编辑区域准备
    SAM 跟踪或手绘 MASK ────────────→ 编辑区域准备 → 官方采样器或 PJ 一采

白色允许修改，黑色保留原视频潜空间，灰色保留原生遮罩强度。原视频编码尺寸须与目标一致，遮罩须同尺寸、同起点；动态目标使用逐帧遮罩，单张遮罩只是全片静态区域。准备节点按 H3 时空跨度取覆盖，边界可能比像素遮罩粗。

无需空间限制时跳过准备节点。若希望二采全画面精修，应在放大后移除输入 noise_mask，否则二采会继续遵守原遮罩。潜空间固定不保证时序 VAE 解码后背景逐像素一致。

## 版本、缓存与限制

完整结果保存在节点拥有的 pj_revisions_* 临时目录，段缓存保存在 pj_segments_*。内存只长期保留小型元数据，成功提交后切换当前完整版本。一二采按绝对视频潜步范围关联，支持不同分段数量和累计多次修改；二采记录已消费的一采版本。

复用操作读取节点当前版本，避免 ComfyUI 的 LRU、RAM_PRESSURE 缓存返回历史结果。相同普通采样请求在当前版本未变时复用磁盘快照，不重复采样；其下游放大、解码仍可能重新执行。更新一采变更时，如果视频待更新但 SIGMAS 不足两项，保留旧完整快照及待更新版本；恢复有效调度后再补做。

第一版仅保证**当前后端会话内**回修，不是跨重启项目存档。节点实例丢失后需重新生成或载入基准。一采修复成功、二采失败时，可以复用一采，仅重试高清更新，不必再次抽卡。

所接 H3 放大器可能在整个时间块上归一化，不能随意截一段放大后声称等同完整放大。本版本保持完整潜空间放大，未通过第三方私有实现增加局部放大缓存。边界复制不改变模型权重量化；分段降低单次采样压力，不保证任意尺寸和时长不超显存。

真实 H3 验证已覆盖：73 帧 320×192 固定基准下的 0、0.2、0.4、0.6 降噪与两组种子；640×384 完整潜空间放大后二采及一采中段回修联动；855 帧、35.625 秒、7 个窗口的接力生成与完整解码，6 处 22 帧边界继承准确。检查结论及运行配置统一记录在 [验证报告](docs/VALIDATION.md)。

另完成实际换鞋参考素材的 73 帧、768×1376 联动验证：仅目标潜步更新，范围外及音频保持，前后完整解码通过。此实验未接 SAM 遮罩，仍检测到既有大幅帧差；不能外推全片画质或 1MP/2MP 长片显存。

这些结果证明采样、版本和范围保护机制可运行，不等于视觉无缝。零重叠样本在部分背景边界仍有帧差峰值，不能宣称没有跳变。尚未按用户的 1MP 换鞋素材完成人工画质验收；右端仍仅为潜空间锁定，增量放大与“已同步／待更新”前端徽标尚未交付。

## 安装与验证

放入 ComfyUI/custom_nodes/ComfyUI-PJ-SegmentSampler，重启后端并刷新前端。使用 ComfyUI 自带 PyTorch、NumPy 及原生 H3 节点，无需安装 Easy、导演台或 SAM 才能使用采样功能。播放器需要 FFmpeg，带声音预览需要 soundfile。

在仓库目录执行：

    & '../../../python_embeded/python.exe' -s -m unittest discover -s tests -v
    Get-Content -Raw js/pj_segment_sampler.js | node --input-type=module --check
    node --test tests/test_planner_widgets.mjs tests/test_purpose_modes.mjs

自动检查覆盖时间、遮罩、版本、原生采样器遮罩适配及 PromptExecutor 阶段跳过，不以替身代替画质验收。独立前端布局页使用 python tests/serve_dashboard.py 启动，访问 http://127.0.0.1:18765；`/purpose` 检查用途页签与 JSON 编辑，不等同完整画布测试。

Windows 本机运行监控使用 PowerShell 7、`nvidia-smi` 和英文性能计数器名称。填写运行任务的 prompt ID 与后端进程 PID；脚本只读队列、历史和日志，每 20 秒记录一次资源，目标任务完成或中断后退出。输出为本地 JSONL、提交快照和结束历史；缺失计数器会记录错误，采样峰值不代表瞬时峰值。`-Once` 只采集一次。

    pwsh -File scripts/monitor_comfyui.ps1 -PromptId TASK_ID -ComfyProcessId PROCESS_ID -LogPath ../../user/comfyui_7188.log -OutputPrefix diagnostics/monitor_run

真实验证使用已有本机权重，请替换模型名和端口。脚本只读取本机队列，另起进程使用原生执行器，不向运行中的服务提交工作流或重启服务：

    & '../../../python_embeded/python.exe' -s scripts/validate_h3_repair.py --output-dir diagnostics/preflight --preflight --server-url http://127.0.0.1:7188 --model H3_MODEL.safetensors --clip H3_CLIP.safetensors --vae H3_VAE.safetensors --lora ''
    & '../../../python_embeded/python.exe' -s scripts/validate_h3_repair.py --output-dir diagnostics/run-01 --server-url http://127.0.0.1:7188 --model H3_MODEL.safetensors --clip H3_CLIP.safetensors --vae H3_VAE.safetensors --lora '' --frames 73 --denoise 0.4

自动分析重新读取普通 [video_tensor, audio_tensor]、检查清单及可选解码帧；清单格式见脚本说明：

    & '../../../python_embeded/python.exe' -s scripts/analyze_segment_outputs.py --before diagnostics/run-01/before.pt --after diagnostics/run-01/after.pt --manifest diagnostics/run-01/manifest.json --before-frames diagnostics/run-01/before_frames.pt --after-frames diagnostics/run-01/after_frames.pt --report diagnostics/run-01/recheck.json

diagnostics/ 已加入 Git 忽略规则。脚本另提供 --denoises/--seeds 矩阵、--refine-smoke 高清联动和 --relay-smoke 长视频接力入口，参数及结果见验证报告。报告将范围外改动、保护失效和交付区间重复/遗漏列为硬失败；亮度、边缘能量和帧间差异仅为风险线索，不能证明画面无跳变。

使用实际素材时加 `--prompt-file 提示词.txt --reference-video 原视频.mp4`，每张产品图分别加 `--reference-image 产品图.jpg`；视频按 24 FPS 读取，可用 `--reference-video-start` 指定起点。参考图须预先组成相同尺寸。`--baseline-file` 接已导出的 `[video, audio]` 张量；配合 `--mask-file` 可读取已有的像素 MASK 张量。未提供遮罩时，报告不将该实验视为完整 SAM 工作流验证。

音频接力对照使用 `scripts/validate_h3_audio.py`：JSON 配置包含 `model/clip/vae/audio_vae`、`width/height/frames`、`steps/scheduler/sampler/seed`、`prompt`，可加 `segment_prompts`、逐张文件路径 `reference_images`、`lora/lora_strength`、`chunk_seconds`。`prefix_file` 可复用第一窗的 `[video, audio]` 张量；`sage_patch: true` 才需要已有 KJNodes。不同对照使用独立空目录。

    & '../../../python_embeded/python.exe' -s scripts/validate_h3_audio.py --config diagnostics/audio_config.json --output-dir diagnostics/audio_run --preflight
    & '../../../python_embeded/python.exe' -s scripts/validate_h3_audio.py --config diagnostics/audio_config.json --output-dir diagnostics/audio_run

脚本导出完整及逐窗 AV 张量、32 kHz WAV 和结构检查报告，不修改采样算法。它不启动服务、不下载权重；执行期间应保持本机队列空闲。语音识别和人工听辨另行进行，结构检查通过不代表对白正确。节点运行无需安装语音识别依赖。
