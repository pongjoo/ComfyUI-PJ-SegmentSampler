# ComfyUI-PJ-SegmentSampler

MiniMax H3 的分段规划、空间编辑准备、一采生成/重抽与二采精修节点。保留现有节点标识、端口类型和旧工作流参数迁移。

## 节点与连接

`PJ_SegmentPlanner → 一采 / 二采`，一采输出可经已有潜空间放大节点送入二采。

- **PJ_SegmentPlanner**：统一分段规则；接入潜空间时读取真实音视频长度，未接入时按约15秒预览。执行后仪表盘自动展开全部分段。图像和音频可用于预览播放器。
- **PJ_H3EditPrepare**：将原视频潜空间与外部编辑遮罩组合成标准H3音视频LATENT，遮罩外保留原视频；不检测目标、不编码视频，也不生成参考条件。
- **PJ_FirstPass_SegmentSampler**：整段采样、分段编辑重抽、22帧接力生成。第二输出是首段潜空间，不是列表。
- **PJ_SegmentSampler**：分段二采，后段固定承接前段视频重叠结果；输出完整采样结果和完整去噪结果，可保留输入音频潜空间。

## 原视频局部替换接线

```text
H3参考生成的第2输出(LATENT) ───→ 编辑区域准备：H3目标音视频潜空间
原视频 → 统一尺寸/截取帧数 → VAE编码 → 编辑区域准备：原视频编码潜空间
SAM跟踪或手绘MASK ────────────→ 编辑区域准备：空间编辑遮罩
编辑区域准备的LATENT ─────────→ 一采：输入潜空间
H3参考生成的第1输出(CONDITIONING) → 引导器 → 一采
分段规划器 ───────────────────→ 一采：分段规划总线
```

搜索“PJ H3编辑区域准备”。原视频编码尺寸必须与H3目标宽高一致，不一定等于参考条件分支的缩放尺寸；原视频先裁到目标合法帧数再编码。遮罩须与编码前视频同尺寸、同起点，逐帧覆盖目标长度；超出目标的末尾遮罩不使用，单张遮罩作为全片静态区域。不能用单张遮罩代替运动物体跟踪。

白色允许生成，黑色保留原视频潜空间。按H3时间跨度和32像素网格取最大覆盖，防止运动目标漏出编辑范围；边界会比原像素遮罩粗。灰色值保留为原生采样遮罩强度，非零区域都视为可编辑。已有目标遮罩进一步限制视频编辑范围，已有音频遮罩保留；没有音频遮罩时音频仍正常采样，原声保留应继续走最终合并的原音频旁路。

开启一采“接缝约束”时，空间黑色区域始终保留原视频；只有空间可编辑区域内的重叠边界承接已有生成内容。采样后和最终拼接后恢复零遮罩区域，消除数值舍入漂移。单段重做不能修改固定交叠，边界缺陷需要把相关相邻段一起选择。改变原视频/遮罩/条件可能使缓存失效；没有缓存会补采。

准备节点输出也可连接标准 `SamplerCustomAdvanced`；PJ一采负责额外的分段接缝和缓存，不是运行空间遮罩的唯一入口。无需空间编辑时跳过准备节点。潜空间保留不保证VAE解码后背景逐像素一致。

## H3 时间规则

- 模型时钟固定24fps；完整视频 `17n+5` 帧对应 `5n+2` 视频潜步，音频为每秒40潜步。
- 示例：124帧 → 视频37步／音频207步；362帧 → 视频107步／音频603步。
- 三节点共用 `segment_timing.py`。采样器始终按实际输入解析规则，不沿用旧预览的音频边界。
- 秒数是规划参考，不是硬上限。自动模式先选择最近的合法段长，再选择最近的可用重叠；同距离时取较长值。起点按5视频潜步／17帧对齐，尾段以真实输入长度为限。
- 例如24fps下输入段长6秒、重叠0.5秒，实际为141帧（5.875秒）与5帧（约0.208秒）；段长6.5秒则就近选158帧（约6.583秒）。无空隙分段最小重叠为5帧，因此输入0也不代表零重叠；采样重叠与最终是否混合画面是两件事。
- 固定数量模式在合法起点上分配指定段数，再就近计算重叠，尾部受剩余长度约束；输入过短时按可用起点数减少段数。自定义模式将起止位置就近对齐。未覆盖区域保留输入，空潜空间中的未覆盖区域不会自动生成内容。
- 已取消手动51帧吸附开关；旧工作流自动迁移，旧API参数仍可载入但不再决定网格。所有规划都由后端统一计算，分段卡片显示实际时长和与前段的实际重叠帧数。
- `fps` 是输入图像序列的播放帧率；规划器按其时长换算为24fps的H3预览，不负责替上游模型重采样视频。
- 规则模式的分段数量只是约15秒参考；要预览实际数量，应接入真实潜空间。

## 界面操作

- 两个采样器的分段规划总线均可不接：未连接时按输入完整长度采样，连接时显示分段选项。一采“生成方式”区分分段编辑、整段采样和22帧接力；整段采样始终忽略分段规则。
- 一采、二采使用原生处理范围下拉框；二采新建节点默认“全部精修”，可按时间或段号定位重做起点，连同全部后续段重建。锁定仅在智能缓存模式显示，且不能阻止前段重做引发的后续重建；输出保持完整长度。
- 种子偏移、参考条件裁剪、重叠过渡及完成后卸载放在“展开高级设置”按钮下，折叠不会重置值。移除采样器说明面板，二采保留输入音频开关常驻。
- 未连接规划总线时隐藏处理范围、段号、锁定和接缝控件；连接后按规划数量显示段号，并随规划更新。保留旧工作流已选的合法段号与设置，不因预览变少而重置；实际边界与数量由后端按输入计算。
- “按分段裁剪参考条件”控制参考视频及音轨条件的时间裁剪，不是独立片段输出。规划器自定义时间范围外保留输入。

## 22帧接力

一采连接规划器，选择“22帧接力”。目标AV潜空间决定最终总长度，规划器的目标段长决定每次调用的窗口长度（包含22帧引导），后端就近匹配H3合法长度。普通切分模式、自定义切点和目标重叠不参与接力规划；规划器卡片仍展示普通分段，接力段号上限读取单独计算的接力数量。二采仍按普通规划精修。

- 第一段正常生成；后续段继承上一段最后7个视频潜步（22帧），通过原生遮罩固定。空间黑色区域仍以原视频为准。
- 拼接时前段拥有重叠区域，后段只追加新增部分，不平均两份画面，也不重复输出22帧。音频按绝对时间边界去重，每处通常为36或37音频潜步，不能直接裁22音频步。
- 例如两个192帧窗口接力，最终为362帧：`192 + 192 - 22`。目标为362帧时输出仍为362帧，不额外缩短。
- “全部生成”重算所有段；“从指定段重做”复用之前的有效缓存，重算指定段及全部后续段。前段缓存缺失、种子或条件变化会从更早处重建；不使用逐段锁定。
- 要生成不同结果，修改目标段种子偏移；前20段可独立调整，后续段默认偏移为段号减一。保持相同种子和配置重跑不代表必然出现新结果。
- 每段仅生成当前窗口噪声并进行采样，结果在CPU拼合。完整输入、完整输出和上游参考编码仍占内存；单次窗口仍须适合模型和显存。这里未接入外置节点的漂移控制补丁，不保证任意时长的画质或人物一致性。

## 重抽、条件与缓存

- 标准 `RandomNoise` 的分段实际种子为基础种子加偏移。分段编辑模式下相同种子在相同绝对位置共享噪声；接力模式按窗口生成噪声。不同偏移改变对应段的初始噪声，`DisableNoise` 仍保持零噪声。
- 一采可按时间裁剪 `minimax_refs` 的参考视频及其音轨；不会重新编码已输入的整段视频语义条件。二采也按时间裁剪参考。参考片段未覆盖当前段时不构造空参考张量。
- 两个采样器都会筛选、裁剪并重定位 `minimax_keyframes`。跨边界的引导片段可保留少量起点之前的上下文，以维持原有token相位。
- 对接 ComfyUI 的 `BasicGuider` / `CFGGuider` 条件接口；自定义引导器或噪声实现需遵守同一接口。同步参考不保证生成动作逐帧跟随参考。
- 缓存由每个节点实例独占，写入系统临时目录 `pj_segments_*`，内存只保留校验摘要。改变输入内容、分段边界、条件、模型或采样配置后自动重算；普通分段模式改变种子仍允许保留已锁定结果，接力模式种子变化使该段及后续缓存失效。
- 缓存读取有磁盘开销，不承诺0秒。节点实例释放或正常进程退出时清理；进程被强制终止可能留下临时文件。缓存不跨重启恢复。没有有效缓存的段会先采样。
- 一采未启用接缝约束时，硬切由后段覆盖重叠区；线性和余弦模式按实际重叠范围融合。二采视频始终保留前段重叠结果；过渡算法仅用于重新生成的音频。

## 二采边界承接

- 默认启用，无需新增连线。读取普通规划的实际重叠，不固定为22帧，也不改变现有帧数规则；无规划时仍整段采样。
- 后段视频重叠区继承已精修的前段，通过原生时间遮罩锁定，并在采样后恢复固定值；多个区间交叠时，较早段拥有共同区域。输出与去噪输出均直接去重拼接，不混合两份重叠画面。
- 输入已有空间遮罩时，黑色区域仍以输入为准。内部时间遮罩不写回输出。音频不套用视频接缝锁定：保留原音时旁路输入，否则沿用音频融合设置。
- 从第N段重做会重算N及全部后续段；多个目标以最早目标为起点。缺缓存或输入/条件变化可能提前重建。重建前清除后续旧缓存，中断后仅保留已完成的连续前缀；锁定和相同种子不能阻止依赖重建。旧工作流中的“仅精修第N段”按这一新语义执行。
- 该约束避免两份独立重叠结果加权造成的混合伪影，不保证段内背景不变、解码像素完全一致或成片无接缝。真实H3画质需要固定种子的短片对照。

## 一采接缝约束（实验）

- 一采新增“接缝约束”开关，默认关闭以保留旧工作流。开启后，首次生成将已生成段的真实重叠潜空间作为后段的固定内容，通过原生 `noise_mask` 在每步采样中约束；视频和音频分别使用各自时间边界。
- 局部重做读取其余有效缓存，在前后重叠区固定旧结果，中间区域重新采样；有空间遮罩时只在可编辑区域承接缓存；多个相邻段一起重做时按时间顺序生成，不默认重做全部后续段。希望修改重叠区中的缺陷时，应一起选择涉及的相邻段。
- 开启后隐藏融合算法，重叠区仅保留一份内容，不再把两份独立结果平均。采样后恢复固定重叠值以消除求解器舍入漂移。自定义区间完全被保留段覆盖时，该段没有可重新生成区域；没有重叠的硬切区间无法获得此约束。
- 首次开启、切换模式或改变规划/输入/条件需重建缓存。缺失缓存的段仍会生成；重建中断会使本轮缓存失效，下次重新建立完整结果。整段不分段模式不使用接缝约束。
- 保护的是潜空间重叠内容，不是逐像素保留相邻画面的保证；VAE时序解码及模型生成质量仍会影响接缝。尚未用真实H3权重完成画质验证，建议先做短片对照。
- 独立采样的线性/余弦融合也已修复包含区间的权重问题：仅实际交叠部分使用分块FP32计算，非重叠部分直接复制，输出不把FP32采样结果降回BF16输入精度，不改变模型权重量化。

## 精修范围

这是基于开源 H3 模型的自定义潜空间精修流程，不等同于官方 H3-Regenerate-2K。后者的发布状态以 [MiniMax官方仓库](https://github.com/MiniMax-AI/MiniMax-H3) 为准。

保留原音功能保证输出音频潜空间不变；音频仍参与联合模型计算，不保证新画面的口型匹配。分段和采样后卸载模型可降低部分显存压力，但不保证无接缝、无质量损失或不会显存不足。超过模型常用时长、高清精修质量和显存峰值需要实际模型验证。

## 安装与验证

放入 `ComfyUI/custom_nodes/ComfyUI-PJ-SegmentSampler`，重启后端并刷新浏览器。使用 ComfyUI 环境已有的 PyTorch、NumPy；播放器另需可用的 FFmpeg，带声音预览需 soundfile。

在本仓库目录使用所属便携包的 Python 执行：

```powershell
& '..\..\..\python_embeded\python.exe' -s -m unittest discover -s tests -v
Get-Content -Raw js/pj_segment_sampler.js | node --input-type=module --check
node --test tests/test_planner_widgets.mjs
```

独立浏览器布局回归页：

```powershell
& '..\..\..\python_embeded\python.exe' -s tests/serve_dashboard.py
```

打开 `http://127.0.0.1:18765`，依次执行4段、20段、变窄、再次4段，检查页面显示PASS且无需拖动节点。页面下方可检查一采三种生成方式、规划断开／重接，以及二采默认值和旧工作流锁定恢复。此页面使用真实前端扩展与轻量DOM控件宿主，不代替完整ComfyUI画布验证。
